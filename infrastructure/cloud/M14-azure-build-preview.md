# M14 Azure Build Preview

## Purpose

This preview explains what will be built for the first M14 Azure pass, why each part exists, and how it will be built.

No Azure resources should be created from this document alone. Treat it as the approval checklist before running live Azure commands.

This first pass is the fast `cloud-dev` path. The goal is to get the development image built in Azure quickly, while reserving slower production-concept learning for the later `prod-sim` environment.

## Current Decision

The first Azure action should be a **`cloud-dev` Azure-side image build** using Azure Container Registry Tasks.

That means Azure builds the `stats-runtime` image from:

```text
infrastructure/containers/stats/Dockerfile
```

The image is stored in Azure Container Registry as:

```text
<acr-name>.azurecr.io/stats-runtime:<image-tag>
```

This proves the M13 container can be built in Azure before we create a running cloud app. `prod-sim` is not part of this first pass because it is the later guided learning environment.

## Why Build the Image First

The current M13 runtime still starts by checking a PostgreSQL-style database host through `DB_HOST` and `DB_PORT`.

Because of that, creating the Azure Container App immediately would need one of these first:

- a temporary reachable PostgreSQL-compatible database endpoint for the current runtime, or
- the M9 Azure SQL persistence migration so the app can use Azure SQL as the operational store.

Building and storing the image in ACR is the safest first cloud step because it confirms the cloud build path without forcing the app to start against an unfinished database migration.

## Phase 1 Resources

These are the only resources needed for the first Azure-side image build.

| Resource | Example Name | Why It Exists |
| --- | --- | --- |
| Environment label | `cloud-dev` | Keeps the first cloud build scoped to the development environment. |
| Resource group | `rg-stats-dev` | Groups the Stats development cloud resources so they are easy to review and clean up. |
| Azure Container Registry | `acrstatsdev001` | Stores the built `stats-runtime` image. |
| ACR Task build run | Generated by Azure | Performs the Docker build inside Azure using the repo root as context. |
| Container image | `stats-runtime:dev` | The deployable M13 runtime image produced by the build. |

## Not Built Yet

These resources belong to later M14 phases and should not be created until the image build and database direction are agreed:

| Resource | Why It Waits |
| --- | --- |
| Azure Container Apps environment | Needed when we are ready to run the container. |
| Stats Container App | Needs a database startup path before it can become healthy. |
| Azure SQL logical server and database | Needs M9 schema, migrations, and persistence adapter decisions. |
| Key Vault | Needed before live secrets are configured. |
| Managed identity | Needed before runtime access to ACR, Key Vault, SQL, and Storage. |
| Storage account and Blob container | Required now that the `AzureBlobStorage` provider backs durable accepted-document storage. |
| Fabric workspace | Reporting model comes after operational persistence is stable. |
| Power BI workspace/report | Dashboard/report delivery belongs after M11 reporting design and data model work. |

## How The Azure-Side Image Build Works

The script is:

```text
infrastructure/cloud/build-stats-acr-image.ps1
```

It performs these steps:

1. Resolve Azure CLI from `PATH` or the standard Windows install path.
2. Confirm the active Azure account.
3. Create or reuse the resource group.
4. Create or reuse Azure Container Registry.
5. Run `az acr build` using the repo root as Docker build context.
6. Store the image in ACR.
7. Print the final image reference.

## Preview Command

Use this command to preview the script operations without creating resources:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\infrastructure\cloud\build-stats-acr-image.ps1 `
  -ResourceGroup rg-stats-dev `
  -Location australiaeast `
  -AcrName acrstatsdev001 `
  -ImageTag dev `
  -WhatIf
```

## Live Build Command

powershell -NoProfile -ExecutionPolicy Bypass -File .\infrastructure\cloud\build-stats-acr-image.ps1 `

## Evidence To Capture

When the live build is approved and run, capture:

- Azure subscription name with subscription ID redacted if included.
- Resource group create/update output.
- ACR create/update output.
- ACR build run result.
- Final image reference.
- Confirmation that no secrets were printed.

## Review Checklist

Before running the live build, confirm:

- The Azure subscription is the intended subscription.
- The location is acceptable for the project.
- The target environment is `cloud-dev`.
- The resource group name is acceptable.
- The ACR name is acceptable and globally available.
- The expected first image tag is acceptable.
- No Container App, SQL database, Key Vault, Storage, Fabric, or Power BI resources will be created in this first build step.
